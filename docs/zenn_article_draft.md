# 日本株向けPoint-in-Time財務×有報リスク変化スコア（148社検証）

日本株のシステムトレードやファンダメンタル・バックテストを組む際、次の2つがボトルネックになりがちです。

1. **先読みバイアス（Look-ahead Bias）と生存者バイアス**: 訂正報告書で過去の数値が上書きされていたり、上場廃止銘柄が欠落していたりする。
2. **有報テキストの定性情報が数値化されていない**: 「事業等のリスク」が前年と全く同じコピペなのか、大きく書き換わったのかをスクリーニングに組み込めない。

これらを解消するため、EDINET API v2 から取得した提出日時ベースの **Point-in-Time（時点整合性）財務データ** に、GPU（`intfloat/multilingual-e5-large`）で算出した **有報「事業等のリスク」前年比変化スコア（`risk_change_score`）** を統合した静的 Parquet / DuckDB データセットの検証パイプラインを構築しました。

---

## 1. 148社で検証した結果：有報の「リスク記述変化度」はここまで割れる

2025年6月および2026年6月に有価証券報告書を提出した上場企業 **148社** を対象に、「事業等のリスク」セクションをチャンク分割＋Embedding平均プーリングし、前年比コサイン距離（`1 - cosine_similarity`）を算出しました。

* **集計対象**: 148社（2025年・2026年提出ペア）
* **下位25%**: `0.000253` 以下（ほぼ前年踏襲・微修正のみ）
* **中央値（50%）**: `0.001543`
* **平均値**: `0.002593`
* **最大値**: `0.023372`（中央値の約15倍）

## 2. 先読みバイアスを防ぐ Point-in-Time スキーマ設計

本データセットでは、指標値を「会計期末（`period_end`）」ごとに上書きせず、`submit_datetime`（提出日時）をキーとして履歴のまま保持します。

Polars または DuckDB で以下のようにクエリするだけで、任意の過去時点 `as_of` で「その瞬間に市場が知り得た最新値」だけを正確に引き出せます。

```sql
SELECT sec_code, filer_name, period_end, metric_name, metric_value, risk_change_score
FROM read_parquet('sample/edinet_pit_sample.parquet')
WHERE submit_datetime <= TIMESTAMP '2026-06-26 00:00:00'
QUALIFY ROW_NUMBER() OVER (
    PARTITION BY edinet_code, period_end, metric_name
    ORDER BY submit_datetime DESC
) = 1;
```
